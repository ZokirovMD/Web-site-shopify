## Что такое ORBIT

Личная операционная система одного человека — студента из Ташкента. Деньги, тело,
питание, время, учёба, бизнес, коллекции, путешествия, новости. Одна вкладка вместо
пятидесяти пяти.

**Горизонт — 30–40 лет.** Это не проект на месяц. Решения принимать соответственно:
границы модулей, чистое ядро, документированная система. Быстрые хаки, которые придётся
переписывать, здесь дороже, чем медленное правильное решение.

### Два механизма, ради которых всё строится

1. **Проекция считает будущее вперёд.** Объявил правило один раз — все модули читают
   из одной проекции.
2. **Клод внутри системы, а не рядом.** Владелец пишет в ORBIT (модуль ДИАЛОГ), агент
   приходит по расписанию или через MCP, отвечает там же и вносит правки. Переключаться
   между чатом и сайтом не нужно — это было его главное возражение.

### Принцип глубины (важно)

Каждый модуль обязан иметь все пять слоёв:

```
ты задаёшь цель → система разворачивает план с числами → ты отмечаешь факт
→ план корректируется → система предлагает следующее
```

**Модуль без всех пяти слоёв — недоделан.** Это относится к учёбе, бизнесу, финансам,
развитию — ко всему, не только к тренировкам.

## Правила кода

### Границы — не нарушать

```
core/     чистая логика. НЕ знает о React, о базе, о Next.js.
          Любая функция вызывается в тесте одной строкой.
db/       схема и запросы. Drizzle.
design/   токены и примитивы. Единственный источник правды по визуалу.
modules/  компоненты + server actions по модулям.
app/      маршруты и раскладка.
mcp/      MCP-сервер ORBIT.
```

**Движок проекций, движок тренировок и движок питания живут в `core/` и покрыты
тестами.** Это ядро продукта, не деталь.

### Обязательно

- TypeScript strict. `any` — только с комментарием почему.
- Деньги — целые числа в минорных единицах. **Никогда `float`.**
- Zod на каждой границе, где данные приходят из браузера.
- Каждая таблица: `user_id`, `source` (manual|claude|rule|import), `source_run`.
- Цвета, размеры, отступы — **только токены** из `design/tokens.css`. Литералов в
  компонентах нет.
- Весь текст интерфейса — в `i18n/ru.json`. В компонентах текста нет.
- Курс валют — данные в базе, не константа.

### Запрещено

- Скруглённые карточки с одинаковым радиусом. У нас фаска, см. брендбук.
- Градиенты, «стекло», светящиеся рамки, неоновые акценты.
- Эмодзи вместо иконок.
- Библиотеки графиков. Рисуем SVG сами, в гирих-грамматике.
- Шрифты Inter, DM Sans, Space Grotesk, Plus Jakarta Sans, IBM Plex, Manrope.
- Узор под данными. Орнамент только: фон ≤4%, пустые состояния, экран входа.
- Геймификация, очки, поздравления, восклицательные знаки в интерфейсе.

### Визуальный ориентир

Владелец просил: **не старомодно.** Современно, чётко, красиво, с приятными анимациями —
на уровне хороших дашбордов. Гирих у нас — это **грамматика** (сетка, узлы, углы 36°,
фаска), а не восточный орнамент поверх интерфейса. Исполнение современное: плотная
информационная вёрстка, табличные цифры, сдержанный цвет, точная типографика,
осмысленное движение.
